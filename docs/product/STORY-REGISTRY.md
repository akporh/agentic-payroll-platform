# Story Registry

The primary traceability table — one row per story **that has been migrated into this hierarchy and has a story file under `stories/`**.

**This is now the full inventory.** All **157** known items have been migrated and hold a full record here, completing Phase 4 under D-027 (2026-07-29). `ID-ALLOCATION.md` answers "what exists" and this file answers "what has a full record" — as of this batch the two give the same number, and there is no migration backlog. **The absence of a story from this registry is now meaningful evidence that no such work exists**, which it was not while the registry was partial.

## Identifiers (D-019, D-020)

Story IDs are `STORY-<nnnn>` and **encode nothing** — no programme name, no capability area, no feature, no sprint, no date. Any identifier that encodes a relationship becomes a lie the moment that relationship changes, and this hierarchy explicitly allows a story's feature assignment to be revised. Readability comes from `title` and the display-name columns; chronology from `sprint_refs`, which sorts.

The superseded `PT-<area>-<nn>` scheme encoded the programme's own name and a position in a one-off retro inventory. Every legacy code is preserved in **`origin_code`**, which is mandatory. Search for `PT-A1-22` and you will find `STORY-0102`.

## Acceptance criteria (D-018)

**Retro-migrated stories carry no acceptance criteria.** Their authoritative criteria stay in the original sprint story file, which this record links to. **Forward-authored stories** — written into this hierarchy by the PM, with no prior sprint file — carry their criteria natively. A retro record is deliberately not standalone-complete; a forward record is.

## Human-readable names (D-016)

`feature_name` is display-only — `feature_id` is authoritative. `validate_registry.py` enforces the match. Never resolve a story's feature by name.

## Schema

| Column | Meaning |
|---|---|
| `story_id` | Stable identifier, `STORY-<nnnn>`. Never reused, never renumbered. |
| `origin_code` | **Mandatory.** Every legacy identifier this work has been known by — provisional PT ID, sprint item code, track code. `·`-separated where more than one. |
| `title` | Short title. |
| `feature_id` | The `feature_id` this story belongs to. Authoritative. |
| `feature_name` | Display-only copy of the referenced feature's current `name`. |
| `classification` | `user-facing story` \| `operational story` \| `compliance story` \| `platform capability` \| `technical enabler` \| `defect/remediation` \| `discovery or architecture item`. |
| `status` | `delivered` \| `in-flight` \| `backlog`. |
| `confidence` | `confirmed` \| `strongly inferred` \| `tentative` \| `requires human classification`. Migrated verbatim; never silently upgraded. |
| `ac_owner` | `source` (retro-migrated — criteria live in the linked sprint file) \| `hierarchy` (forward-authored). |
| `sprint_refs` | Sprint(s)/track(s) that delivered this story. |
| `evidence_refs` | Path(s) to delivery evidence. |
| `story_file` | Relative path under `stories/`. |
