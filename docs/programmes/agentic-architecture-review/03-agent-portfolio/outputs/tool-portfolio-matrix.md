## Cross-cutting requirements for every tool (not repeated per-row above)

1. **Independent workspace-ownership enforcement is mandatory for every tool**, regardless of whether the underlying repository function already scopes correctly — do not assume it does (Stage 02 Principle 11, motivated directly by the `get_reconciliation` gap). This is the single most important cross-tool requirement in this matrix.
2. **No tool should return an LLM-computed conclusion where a deterministic computation already exists or should exist** — `get_enrollment_status` and any future reconciliation-diff tool are the two concrete cases identified; the general rule applies to any tool proposed later.
3. **Decimal values returned to any tool must be serialized as strings**, per the source document's own stated rule — this is a project-wide exception to the existing JSONB-float convention, specific to LLM-visible context.
4. **A tool that references a nullable structured field it depends on (e.g. `component_trace_jsonb`) must have an explicit, specified behavior for the null case** — currently only `explain_component_trace` was identified as having this gap, but the rule should apply to any future tool with a similar dependency.
